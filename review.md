
# Проверка диаграммы вариантов использования

## 1. Цель проверки
Проверить правильность оформления UML-диаграммы вариантов использования системы «Бронирование аудиторий».

## 2. Чек-лист проверки

| Критерий | Результат |
|---|---|
| Акторы находятся вне границы системы | Да |
| Акторы обозначают роли или внешнюю систему | Да |
| Овалы описывают цели акторов | Да |
| Формулировки вариантов использования начинаются с глагола | Да |
| Порядок выполнения не изображён стрелками | Да |
| Граница системы обозначена прямоугольником | Да |
| Каждый вариант использования связан хотя бы с одним актором | Проверить на итоговой диаграмме |
| Количество связей include и extend не превышает трёх | Да, две связи |
| Назначение системы понятно | Да |
| Диаграмма содержит не более десяти овалов | Да, шесть овалов |

## 3. Используемые отношения

### Include
«Забронировать аудиторию» включает «Проверить доступность аудитории».

Проверка доступности необходима перед созданием бронирования.

### Extend
«Заказать оборудование» расширяет сценарий «Забронировать аудиторию».

Заказ оборудования является дополнительным действием и выполняется при необходимости.

## 4. Замечания по диаграмме
- Проверить направление стрелки `<<include>>`: она должна указывать на включаемый вариант использования.
- Проверить направление стрелки `<<extend>>`: она должна указывать на основной вариант использования.
- Убедиться, что отношения обозначены пунктирными стрелками.
- Проверить наличие связей акторов со всеми вариантами использования.
- Убедиться, что элементы расположены внутри или снаружи границы системы в соответствии с правилами UML.

## 5. Вывод
Диаграмма содержит шесть вариантов использования и две связи между ними. Её структура соответствует основным принципам UML при условии успешного прохождения всех пунктов проверки.
